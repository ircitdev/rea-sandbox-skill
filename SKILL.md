# REA в песочнице

REA объединяет разбор JS, сайтов, .NET и бинарников под одной командой. У него много движков и условий, а результат легко переоценить. Скилл нужен, чтобы запустить его без следов на машине и не выдать отчёт инструмента за полную правду.

Дальше `$SKILL` — папка скилла, `$W` — новая пустая папка вне проекта (scratchpad).

## Границы

- Анализировать только свою систему или цель, на которую есть явное разрешение. Анализ чужих закрытых программ — только если это допускают лицензия и закон.
- Только пассивно: читать код открытой вкладки или файл. Не вызывать найденные эндпоинты, не перебирать пароли и не отправлять формы.
- Логин и пароль вводит сам пользователь в отдельном окне. Причина: пароль не должен проходить через агента.
- Результат про защищённость не говорит ничего, если права доступа не проверялись. Так и писать.

## 1. Выбрать маршрут

| Цель | Что запускать | Что нужно |
|---|---|---|
| Сайт, панель | `analyze-web-bundle` | Отдельный Chrome |
| Папка с JS, Electron, ASAR | `analyze-javascript-application` | Только Node |
| .NET-сборка | `inspect-managed-artifact` | Только Node |
| PE (Windows) | `analyze`, `decompile` | Ghidra |
| ELF, Mach-O | `analyze`, `decompile` | Linux или macOS: Ghidra, Kuna, Hopper |

Матрица платформ — в `references/engines.md`, читать перед установкой движка. Главное: на Windows Ghidra принимает только PE, а Kuna и Hopper не работают. Для ELF и Mach-O на Windows нужен одноразовый контейнер Linux.

## 2. Установить изолированно

```bash
bash "$SKILL/scripts/bootstrap.sh" "$W"             # Node и REA
bash "$SKILL/scripts/bootstrap.sh" "$W" --ghidra    # + JDK 21 и Ghidra 12.1.x
bash "$SKILL/scripts/bootstrap.sh" "$W" --kuna      # + Kuna, только Linux и macOS
source "$W/env.sh"
```

Скрипт скачивает всё в `$W`, сверяет SHA-256 и ставит пакет с `--ignore-scripts --omit=optional`. Системных установок нет. После `source` доступна команда `rea`, проверка — `rea doctor`.

`rea setup` не запускать без просьбы: он правит `~/.claude.json` и ставит скилл. Как это сделать правильно — раздел 6.

## 3. Разобрать сайт

```bash
node "$SKILL/scripts/cdp_browser.mjs" start --dir "$W/chrome" --url "https://цель/"
# если нужен вход: окно видимое, пользователь входит сам, ждать его подтверждения
node "$SKILL/scripts/cdp_browser.mjs" list --dir "$W/chrome"     # берём targetId
```

Браузер запускается с пустым профилем и CDP только на `127.0.0.1`. Основной браузер подключать нельзя: в нём чужие сессии.

```bash
rea analyze-web-bundle http://127.0.0.1:9333 <targetId> \
  --allowed-origins https://цель --observation-ms 3000 \
  --analysis-timeout-ms 60000 --detail summary --evidence_output "$W/ev.json" --format json \
  --view '{"kind":"javascript-routes","collection":"routes","fields":["path","confidence"],"limit":60}'

node "$SKILL/scripts/evidence_report.mjs" "$W/ev.json"
node "$SKILL/scripts/cdp_browser.mjs" stop --dir "$W/chrome"     # закрыть и удалить профиль
```

`stop` обязателен: в профиле остаётся сессия пользователя. Серверная сессия при этом живёт дальше, об этом стоит сказать.

Evidence может содержать данные авторизованной страницы. `evidence_report.mjs` считает маркеры секретов, не показывая значений. Содержимое inline-скриптов в чат и в память не выводить.

## 4. Разобрать JS и бинарники

```bash
rea analyze-javascript-application /путь --analysis-timeout-ms 120000 \
  --detail summary --evidence_output "$W/js.json" --view '<как выше>' --format json
rea analyze файл --format json
rea decompile файл entry --format json
```

В системных бинарниках символов обычно нет. `main` ищется по цепочке: `entry` → CRT-старт → функция, чей результат уходит в `exit`. Точка входа называется по-разному: `entry`, `_start` у Ghidra, `EntryPoint` у Hopper.

Флаги и формат запросов к Evidence — в `references/cli.md`, читать при первой ошибке `invalid_request`.

## 5. Проверить результат

Без этого шага отчёт ненадёжен. Инструмент показывает, что он нашёл, но не доказывает, что больше ничего нет.

- **Эндпоинты.** REA ловит литералы `fetch('/x')`, но не `var URL = '/x'; fetch(URL)`; вызовы jQuery тоже могут не попасть. Выборочно сверять поиском по `fetch(`, `$.ajax`, `XMLHttpRequest`. Для полного списка брать маршруты из приложения.
- **Статус `partial`** ещё не значит ошибку в коде. REA разбирает скрипты как модули, поэтому слово `interface` как имя параметра даёт `partial`, хотя файл валиден. Сверять через `node --check`, а затем парсером в режимах `script` и `module`.
- **Маршруты: 0** на серверном приложении — норма: инвентарь рассчитан на SPA.
- **Декомпиляция.** Сверять с наблюдаемым поведением программы или вторым движком. Выводы ИИ-агента поверх REA тоже проверять: он может добавить деталь, которой в коде нет.
- **Таймаут** определяется содержимым файла, а не размером. Снижение `--max-semantic-nodes*` не помогает. Выбрать конкретные файлы через `--source-path` или поднять лимит, а в отчёте написать, что файл не разобран.

## 6. MCP и подключение к агенту

Проверить сервер без правки конфигов:

```bash
node "$SKILL/scripts/mcp_probe.mjs" "$W"
```

Проверить в настоящем агенте — через временный конфиг: `claude -p "…" --mcp-config файл.json --strict-mcp-config --allowedTools mcp__rea`.

В конфиге задать `REA_MCP_OUTPUT_SCHEMA_PROFILE=off`. Иначе `tools/list` весит около 3,4 МБ; с `off` — около 300 КБ. В 6.8.0 `compact` размер не уменьшал.

Постоянная регистрация — только по просьбе пользователя и не из временной папки: `setup` записывает абсолютные пути к Node и `rea.mjs`, и после очистки папки регистрация сломается. Порядок: сначала `rea setup --client <агент> --dry-run`, запомнить исходный ключ `mcpServers`, потом применить.

Откат — `rea uninstall`, но у него нет `--dry-run` и `--client`: он снимает REA у всех агентов сразу. Копировать `~/.claude.json` обратно целиком нельзя, работающий Claude Code постоянно его переписывает. После отката удалить `~/.claude.json.rea.backup*`, созданные этим запуском.

## 7. Отчёт

Писать отдельно: что проверено, что найдено, что пропущено, что осталось непроверенным. Указывать версии REA и движков, платформу и время. Не называть результат аудитом безопасности. Документы с внутренними адресами не коммитить и не публиковать.

Перед завершением убедиться, что не осталось процессов Chrome и Java, контейнер удалён, порт CDP свободен.
